**固定的自动语义自评模板（AUTO-0.2-SELF-REVIEW-1）**

当前作答 Agent 可以在每题 `output/self_review.json` 中，按照下面的固定模板记录事实、完整性和可用性意见。该文件是 `CANDIDATE_SELF_EVALUATION`，不计入程序核验分，不覆盖已知 FAIL。无需人工评分、人工仲裁或第二个模型；题集不会为自评新增模型调用。没有自评文件仍能完成核验和报告。

先保存实际交付，再根据可读取的产物自评。未观察到、未执行或当前环境无法确认的维度填 `null`，说明原因；不要把未知填成 0，也不要把自行声称的成功当成浏览器、Office 引擎或模拟服务的独立观测。

**统一的 0–4 锚点**

| 分数 | facts：事实与依据 | completeness：任务完整性 | usability：产物可用性 |
|---|---|---|---|
| 4 | 已观察的关键事实和结论均有本地材料支撑，没有已知矛盾或无依据关系。 | 所有明确要求的交付、必需内容和指定边界均完成。 | 已观察的全部指定操作有效，产物清晰、可读、便于使用。 |
| 3 | 核心结论正确，存在不改变结论的小范围精度、说明或引用缺口。 | 核心交付完整，少量非关键内容缺失。 | 主要操作有效，存在轻微展示、说明或操作上的障碍。 |
| 2 | 核心信息部分可信，至少一项关系或依据尚不充分，尚不能证明主结论完全正确。 | 完成部分主要要求，仍缺一项重要内容或边界。 | 部分主要操作可用，使用者需要额外解释或处理才能完成任务。 |
| 1 | 观察到会影响判断的错误陈述或明显矛盾，仍保留少量正确事实。 | 缺少核心交付或多数重要要求，仅有有限有效内容。 | 多个主要操作不可用，仍有少量可读取或可操作内容。 |
| 0 | 证据证明主结论或关键事实实质错误。 | 没有形成任务要求的有效交付。 | 证据证明产物无法打开、无法呈现或无法完成任何指定主要操作。 |
| null | 现有证据不足，无法确认。 | 无法观察交付是否完整。 | 当前环境无法验证可用性。 |

每个维度都包含 `score`、1–1000 字的 `reason` 和 `evidence` 数组。分数为 0–4 的整数；布尔值、浮点数和字符串不是分数。给出数字分时，至少提供一项实际存在且可定位的本地产物证据。证据不足时允许 `null` 和空证据数组。不同维度可以使用同一个文件，但应写明各自的判断依据。

下面是格式示例；理由和分数须根据本次产物填写，不能照抄为测试结果：

```json
{
  "template_version": "AUTO-0.2-SELF-REVIEW-1",
  "dimensions": {
    "facts": {
      "score": null,
      "reason": "尚未完成对所有关键结论的核对，保留未知。",
      "evidence": []
    },
    "completeness": {
      "score": 3,
      "reason": "已保存主要交付；仍缺少一项非关键说明。",
      "evidence": [
        {
          "path": "response.json",
          "locator": "/result",
          "claim": "result 中列出了本次交付的相对路径。"
        }
      ]
    },
    "usability": {
      "score": null,
      "reason": "尚无当前产物的渲染或交互观测。",
      "evidence": []
    }
  },
  "commentary": "说明本次产物的语义、叙事或视觉体验；不重复宣称尚未观察的操作成功。",
  "known_limitations": ["示例文字需要替换为本次实际局限。"]
}
```

**证据定位与绑定**

`path` 相对于本题 `output/`。只允许实际存在的普通文件，禁止绝对路径、`..` 和符号链接。不能访问网络或引用其他题目的产物。每个维度最多 20 项证据；`locator` 和 `claim` 分别最多 1000 字。`commentary` 最多 4000 字，`known_limitations` 最多 20 条，每条最多 1000 字；没有已知局限时填空数组。

| 证据文件 | locator 格式 | 当前核验范围 |
|---|---|---|
| JSON，例如 response.json | `/result`、`/result/workbook` | 检查 JSON Pointer 指向的值实际存在。 |
| CSV | `columns:Month,Amount` 或 `rows:1-3` | 检查列名或数据行范围存在，行号不含表头。 |
| 文本、HTML、代码、日志 | `body` 或 `lines:1-10` | 检查文件正文或行号范围存在。 |
| XLSX | `cells:Summary!B2` | 检查原生单元格存在。 |
| PPTX | `slides:1` | 检查对应 slide 部件存在。 |
| 本次真实截图 PNG/JPEG/WebP/GIF | `image:whole` | 检查文件存在及基本图像签名，不把截图自动认定为评估器生成。 |
| 本次 PPT 或文档导出的 PDF | `document` | 检查文件存在及 PDF 签名；可以在 claim 中描述关注内容，不声称程序已经核验特定页的语义。 |

核验器为有效证据记录文件 SHA-256，并与维度、路径、定位和陈述一起保存。当前报告外层同时绑定 run_id、scenario_id、输入与产物。文件哈希用于识别实际引用的文件字节；定位存在和哈希匹配不证明陈述正确，也不把当前 Agent 的自评变成独立评审。HTML 源码存在不能代替真实交互验证，截图存在不能代替界面行为验证。

**格式错误的处理**

`validate_self_review(value, output_dir)` 返回 `valid`、`errors`、`template_version`、`dimension_scores` 和有效证据列表。格式、路径、文件或定位错误记录为 `valid=false`，原始内容由报告保留，不阻塞程序核验。修正自评文件后可生成新报告；不得修改原报告中的已知程序错误来配合自评分。

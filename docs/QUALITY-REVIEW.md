# COUNSO-Benchmark 质量审查

审查日期：2026-10-14。对象：AUTO-0.2 题集、核验实现、控制测试与公开说明；本轮兼容修正后工具版本为 0.2.1。没有调用候选模型，未生成模型排名。

## 判断

**它是面向办公 Agent、具备较扎实产物核验的专项题集，适合回归与诊断。现有证据不足以认定它是通用领先或“特别优秀”的综合评测。**

优势集中在“交付物是否正确且可继续使用”，与业务场景有较好关联；主要短板是场景广度、独立语义/视觉评审、真实 Agent 对比以及统计设计。适合明确范围地对外介绍，不宜直接宣称行业领先。

## 三类场景

| 方向 | 已有优势 | 主要不足 | 合适用途 |
|---|---|---|---|
| 日常办公事务 | 16 个主任务；区分版本与权威、批准状态、未知信息、对象歧义；来源与草稿恢复需要题内服务观测 | 写作与长文质量主要靠有限规则和候选自评；缺少真实长期协作、真实连接器与租户验证 | 结构化业务判断、事实与权限边界回归 |
| 文件和工具 | 12 个主任务；核对原生图表、实际公式范围、追加与复制、嵌入数据、定向保留及文件内容哈希 | Excel 求值有支持范围；PPT 仅两题；缺少复杂 Word/PDF、扫描件、更多工作簿和大规模文件异构样本 | 表格、PPT、CSV 与文件完整性的专项验收 |
| 生成式 UI | 6 个主任务；固定核验器真实操作，覆盖数据状态与多阶段产物；截图和资源指纹可追溯 | 仅固定行为约定，较依赖明确控件契约；无完整响应式、键盘、读屏、视觉和开放需求测试；种子变体仅三道销售 UI | 离线业务界面的功能与数据回归 |

具体任务见 [CASEBOOK](CASEBOOK.md)，不能将少量代表题视作日常办公的全部工作分布。

## 设计中值得保留的部分

1. **交付物与结果优先。** Excel 与 PPT 读取候选实际 OOXML、引用和嵌入数据；文件整理核对完整集合与字节；UI 由核验器控制浏览器。模型声称“完成”不直接获得通过。实现见 [artifact_tasks.py](../counso_bench/artifact_tasks.py)、[office_check.py](../counso_bench/office_check.py)、[ui_worker.cjs](../counso_bench/ui_worker.cjs)。
2. **不隐去失败或未知。** 固定题单保留未提交任务；已知必需失败优先于未知；关键错误不能被其他维度平均掉。实现见 [automation.py](../counso_bench/automation.py) 与 [评分口径](SCORING.md)。
3. **有正例、负例与独立业务 Oracle。** 测试包含错误缓存、错误嵌入数据、篡改检查集合、旧服务观测与同 seed 复现；业务 Oracle 不导入素材生成器来计算答案。它们支持“核验器可用”的结论，不能替代候选模型的区分效度。
4. **说明证据强弱。** 题内 mock、候选自评、模型身份声明与生产操作分开。执行包和输入指纹限制静默混用不同版本；不能据此宣称强隔离或路由认证。

## 本轮发现与修正

| 问题 | 影响 | 本轮处理 |
|---|---|---|
| 文件整理与冻结清单采用本机路径分隔符 | Windows 将正确的嵌套目录误判为缺文件；冻结包与执行身份跨平台不一致 | 文件集合、清单、ZIP 和执行指纹使用 `/`；增加源码 ZIP 解包后重新校验的回归 |
| Git 自动换行与 JSON 写入换行不一致 | 下载后可能出现大量字节哈希不匹配；工作区换行缓存也可能与 Git 原始对象不同 | `.gitattributes` 禁用 Git 字节转换，冻结前核对原始对象；新 JSON 输出固定 LF，增加开启 autocrlf 的真实 Git 克隆回归 |
| 包名、ZIP 根目录和模块版本仍沿用旧标识 | 对外名称与实际工具版本不一致 | 统一 COUNSO-Benchmark；Python 分发名 `counso-benchmark`；工具版本 0.2.1，评分契约保持 AUTO-0.2 |
| 符号链接测试在无创建权限的 Windows 主机直接报错 | 主机权限问题混入实现回归结果 | 将相关检查拆开；仅真实链接控制在 WinError 1314 时明确跳过，其他路径检查仍执行；运行时防护不变 |
| 公开仓库仍带“未授权公开发布”的旧许可说明 | 当前发布状态与说明冲突 | 更新公开可读状态，保留权利边界，不擅自增加开源再分发授权 |

修复改变执行包指纹；已有作答须使用其原冻结版本或新建尝试，不能回写历史成绩。复跑证据见 [本轮验证](VERIFICATION-20261014.md)。

## 优化优先级与验收条件

以下为后续建议，尚未实现，也没有计入当前覆盖。

| 优先级 | 工作 | 完成条件 |
|---|---|---|
| P0 | 验证真实候选 Agent 的区分能力 | 固定模型身份来源、工具/预算、题单和输入；公布逐题产物、失败/未知原因与重复运行；确认正确但不同写法不会普遍误罚 |
| P0 | 增加独立语义与视觉评审校准 | 候选与评审分开；用冻结的正误样本核对误判与漏判；保留不同意见，不能让审美分抵消数据或授权错误 |
| P1 | 扩展 UI 与 Office 的实际使用覆盖 | 增加小屏、键盘、读屏、布局溢出、错误/加载状态；增加复杂 Excel、PPT 与 Word/PDF，逐项配置独立检查和错误对照 |
| P1 | 扩展未公开保留集与跨题数据变体 | 不只改三道 UI 的销售金额；覆盖不同业务实体、材料布局和干扰证据；保留集不用于调参；检查成绩与原题的变化 |
| P1 | 验证真实连接器工作流 | 在明确授权的测试账户中核对最终状态、幂等、保留范围和权限；独立标识 live 证据，不与 mock 成绩混算 |
| P2 | 形成可解释比较报告 | 同时报告成功、失败、未知、覆盖、耗时/费用与工具条件；重复次数由方差和决策需求确定，再选合适的区间与配对比较方法 |

在这些条件完成前，建议对外采用：**“覆盖三类业务场景、以实际产物和受控交互核验为核心的 Agent 评测题集。”**

# Development verification gates

These are requirements for future verified use, not a record of completed experiments. Reference/mutation checks do not create a model performance table.

1. Clean installation from declared local source or lock-resolved official dependencies; record actual commands and versions in a caller-local output directory.
2. Office full chain: public input handoff, named provider, generated files and actual synthetic tool events, schema-bound factual report. Missing facts remain UNKNOWN; protocol failure is separate from business facts and unsafe effects.
3. Actual UI acceptance: use an authorized supported browser for reference and deliberate controls. Genuinely change dates/nondefault selections, update source, correct invalid input, add/remove and choose conflict Reapply/Discard. Code checks and prepared reports cannot establish browser PASS.
4. Provider/platform boundary: verify each optional live model or platform adapter against its own supported contract. Standalone HTML, Dust Frames and A2UI are separate runtimes; native Counso remains UNKNOWN without actual integration evidence.
5. Result interpretation: preserve fixed denominators/coverage for UNKNOWN. Separate business errors, ordinary functional failures, integration faults, instrumentation gaps and proven safety effects. Do not infer false completion from prose patterns or a stable winner from one generation.
6. Legal/input hygiene: separate public fictional inputs from evaluator controls, disclose instruction-only isolation, retain applicable third-party licenses and obtain any required project redistribution grant.
7. Release review: independently review immutable source, verify its source-only inventory and package contents, and obtain explicit authorization for any subsequent upload, publication or CI activation.
